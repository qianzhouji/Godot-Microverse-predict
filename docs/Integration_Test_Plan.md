# Activity System V2 集成测试计划

**版本**: 1.0  
**创建时间**: 2026-04-08  
**状态**: 进行中

---

## 测试目标

验证Activity System V2各组件协同工作正常：
1. 时序系统正确触发Click和协调
2. Agent生成自然语言决策并提交
3. 协调器收集决策并调用LLM分配活动
4. Agent接收并执行活动序列
5. 专注度系统正确影响奖赏和信息接收
6. 双向奔赴机制正常工作

---

## 测试环境

- **Godot版本**: 4.x
- **LLM**: Ollama + qwen2.5:7b
- **测试场景**: School.tscn
- **测试Agent数量**: 2-3个（便于观察）

---

## 测试用例

### TC01: 基本流程测试

**目标**: 验证完整V2流程跑通

**步骤**:
1. 启动游戏，加载School场景
2. 启动TimingSystem
3. 观察第一个Click触发
4. 检查Agent是否生成自然语言决策
5. 检查协调器是否收集决策并调用LLM
6. 检查Agent是否接收活动序列
7. 检查Agent是否执行活动

**预期结果**:
- Agent生成类似"我想去图书馆自习"的决策
- 协调器成功调用LLM并返回活动分配
- Agent执行MOVE_TO活动
- 控制台无错误输出

---

### TC02: 双向奔赴测试

**目标**: 验证双向奔赴机制

**步骤**:
1. 设置Agent A决策: "我想和B对话"
2. 设置Agent B决策: "我想和A对话"
3. 触发协调
4. 检查LLM是否检测到双向奔赴
5. 检查两个Agent是否分配到相同目标位置

**预期结果**:
- 协调器检测到双向奔赴
- 两个Agent的MOVE_TO目标位置相同（或非常接近）
- 两个Agent成功相遇

---

### TC03: 单向意图测试

**目标**: 验证非双向奔赴时各自独立执行

**步骤**:
1. 设置Agent A决策: "我想和B对话"
2. 设置Agent B决策: "我想去图书馆"
3. 触发协调
4. 检查两个Agent的分配结果

**预期结果**:
- A移动到B的原位置
- B移动到图书馆
- A到达后发现B不在（下次决策处理）

---

### TC04: 专注度系统测试

**目标**: 验证专注度影响奖赏计算

**步骤**:
1. Agent开始LISTEN活动，专注度30%
2. 等待多个Click
3. 检查ActivityManager的奖赏计算
4. 检查InformationReceiver的信息接收

**预期结果**:
- 实际奖赏 = 理论奖赏 × 0.3
- 信息接收比例约为30%

---

### TC05: 三步缓存测试

**目标**: 验证三步活动缓存执行

**步骤**:
1. 协调器分配3步活动序列
2. 观察3个Click周期
3. 检查每步是否正确执行

**预期结果**:
- Click #1: 执行Step 1
- Click #2: 执行Step 2
- Click #3: 执行Step 3

---

### TC06: 活动中决策测试

**目标**: 验证活动中可决策停止/更换

**步骤**:
1. Agent开始活动（如听课）
2. 等待多个Click
3. 观察Agent是否进行活动中决策
4. 检查MVT最优时间计算

**预期结果**:
- 每次Click都触发体验+决策
- 达到最优时间后可能决策停止

## 预期问题及解决方案

| 问题 | 可能原因 | 解决方案 |
|------|----------|----------|
| LLM调用超时 | 模型加载慢 | 增加超时时间或预热模型 |
| 坐标计算错误 | 场景缩放问题 | 检查坐标转换逻辑 |
| 活动不执行 | 缓存索引错误 | 检查activity_cache和current_activity_index |
| 专注度不生效 | context传递错误 | 检查ActivityManager._distribute_click_reward |
